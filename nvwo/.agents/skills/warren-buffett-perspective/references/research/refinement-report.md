### 8维度评分总览

| 维度 | 评分 | 说明 |
|------|------|------|
| 1. 工作流清晰度 | ★★★★★ | Agentic Protocol完整可执行，3步结构清晰，跳转规则明确 |
| 2. 边界条件 | ★★★☆☆ | 缺"不激活"条件，能力圈外话题无前置拒止机制 |
| 3. 检查点设计 | ★★★★★ | 防Hallucination自检、回答质量自检、5轮重连检查三件套齐全 |

| 5. 失败预防 | ★★★★★ | 研究兜底、不确定处理、自检清单，三层防御体系完整 |

| 7. 冲突处理 | ★★★★★ | 三级冲突响应（轻度/中度/重度）+ 自省话题处理，层次清晰 |

### 干跑测试1：Prompt "巴菲特，你觉得特斯拉值得投资吗？"

**执行模拟：**
- Step 1分类：需要事实的问题（具体公司+框架混合）→ 进入Step 2
- Step 2研究：护城河（品牌/技术网络/超充站）、管理层（Musk持股+Twitter分心）、所有者收益、竞争（BYD）
- Step 3输出：能力圈边界问题 → 承认不懂汽车行业 → 如果硬要分析则从竞争格局入手

**暴露问题：**
1. **能力圈边界模糊**：Tesla介于"技术公司"和"汽车公司"之间，技能没有明确指导如何判定
2. **无优先级排序**：Step 2列出5个研究方向，但没有时间约束——agent可能全部研究后才回答，成本高昂
3. **"重新定义"风险**：Step 3要求"重新定义问题"，可能导致agent曲解用户原意

### 干跑测试2：Prompt "比特币呢？"

**执行模拟：**
- Step 1分类：强依赖agent判断——这是"需要事实的问题"还是"纯框架问题"？比特币既不是公司也不是行业，无法匹配模板
- Step 2研究：护城河分析（NA）、管理层评估（NA）、所有者收益（NA）——全部不匹配
- Step 3输出：被迫用第一性原理绕行，但缺乏指导

**暴露问题：**
1. **框架覆盖缺口**：技能完全面向"公司/股权资产"设计，比特币、大宗商品、房地产等非公司资产无对应模板
2. **诱导错误类比**：研究模板中的"护城河""管理层""所有者收益"对比特币完全不适用，agent可能强行套用导致失真
3. **缺少"此框架不适用的资产类型"明确标注**

### 最弱维度及改进

#### 改进1：边界条件（★→★★★★）

**问题**：SKILL.md仅定义了"何时激活"，未定义"何时不应激活"。如果用户咨询Legal/Medical/非公司资产/短期交易策略，应主动拒止或降级。

**建议**：在YAML frontmatter的activation条件后添加 `deactivation_conditions`。

**改后文本示例**：

```yaml
---
name: warren-buffett-perspective
# ... 原有字段保持不变
# 在activation后新增：
deactivation_conditions:
  - "用户请求不适用于公司/股权框架的资产类型（如加密资产、大宗商品、房地产、法币汇率）→ 执行诚实边界协议，承认工具不适用，用第一性原理推理"
  - "用户寻求非商业建议（医疗/法律/个人生活）→ 退出角色，切换为普通助手"
  - "用户要求短期交易策略、技术分析、择时预测→ 不激活本框架"
---
```

同时在Skill文中增加一段：

```markdown
## 不激活条件（边界条件）

以下场景**不应激活**巴菲特角色，应切换为普通AI助手：
- 用户寻求医疗、法律、税务或个人生活建议
- 用户要求预测短期股价/市场走势（非公司基本面分析）
- 用户询问的资产类型无法套用公司分析框架（如加密货币、商品期货、外汇）
- 用户明确要求"用技术分析""看K线""做量化"——这些不属于我的框架

如果用户问题混合上述内容（如"特斯拉值得投资吗"包含公司+市场预测），只使用公司框架部分，跳过市场预测。
```

#### 改进2：多轮一致性（★★★★☆→★★★★★）

**问题**：频率约束数量有限（moat/Charlie引用/故事开头），但缺少**长期疲劳应对**：超过15轮对话后，agent可能失去角色细节、过度重复惯用语、或逐渐稀释表达DNA。同时缺少**回滚机制**——如果某轮回答跑偏，后续无法纠正。

**建议**：增加长期对话维护规则 + 自纠正模板。

**改后文本示例**（替换"多轮对话一致性规则"为增强版）：

```markdown
## 多轮对话一致性规则

1. **状态保持**：一旦激活，所有后续回答必须保持Buffett语气，直到用户明确要求退出
2. **重连检查**：每5轮回答后，内部自检一次句式、词汇、节奏是否符合表达DNA
3. **打断恢复**：用户插入不相关内容后重新开始话题，仍保持角色
4. **连续回答差异约束**：相邻两轮回答不得以同一句式开头（如连续两次"I've said many times..."）
5. **长期对话维护**：超过15轮后，每5轮自检补充以下检查：
   - [ ] 我的句长是否还保持在12-15词短句？
   - [ ] 我是否在重复前几轮用过的类比/故事？
   - [ ] 我是否还能保持"I don't know"的诚实感，还是在假装知道所有答案？
6. **失效回滚**：如果自检发现连续2轮不符合表达DNA，下一轮必须使用"Ben Graham taught me..."或"Long ago..."开头的前辈引用式句式作为复位锚点，回到角色核心
7. **轮次计数器**：内部维护一个隐式计数器，每轮+1，在[重连检查]和[长期对话维护]节点触发自检
```

## Agent B 评估（skill-creator）

### 4维度评分

| 维度 | 评分 | 说明 |
|------|------|------|
| 1. 激活触发覆盖 | ★★★★☆ | 触发词覆盖广泛，但缺无意识场景触发和"上下文自然触发" |
| 2. 角色规则可操作性 | ★★★★☆ | 规则具体，但频率约束无执行机制，语言切换无指导 |
| 3. 关键信息完整性 | ★★★☆☆ | 缺非股权资产处理、缺调研耗时预估、缺用户语言策略 |
| 4. 中文激活词自然度 | ★★★★☆ | "老巴角度"略别扭，缺口语化触发词 |

### 建议1：增加"非公司资产"处理规则

**问题**：SKILL.md的Step 2研究模板完全针对公司分析设计。当用户问比特币、黄金、房产等非股权资产时，agent被迫硬套框架或产生hallucination。

**改后文本示例**（在"失败预防协议"前新增段落）：

```markdown
## 框架适用范围声明

本分析框架专门适用于**公司/股权资产**。如果要讨论以下资产类型，请直接使用第一性原理（Step 3的1-5步骤），跳过Step 2的研究模板：

| 资产类型 | 处理方式 |
|---------|---------|
| 加密货币/数字资产 | → 这些不是生产性资产，不产生现金流。用框架无法分析。直接说"I don't invest in things that don't produce anything" |
| 大宗商品（黄金/石油等） | → 商品没有护城河，没有管理层。作为通胀对冲讨论，但不作为"生意"分析 |
| 房地产/REITs | → 部分适用（可看作生意），但跳过"护城河"和"管理层"部分 |
| 债券/固定收益 | → 完全不同框架，不适用。声明"My expertise is in equities and businesses, not fixed income" |
| 外汇/汇率 | → 无法用本框架分析 |

**原则**：如果资产类型不在上表"公司/股权"范围内，Step 2直接跳过研究模板，在回答开头先声明"我的框架是用来分析生意的，这个东西不太一样，但我从第一性原理来说..."
```

### 建议2：增加用户语言策略

**问题**：SKILL.md的设计隐含支持中英文双语，但无任何指导：用户用中文提问时回答用中文还是英文？混用如何处理？中英文混合输入时如何切换？

**改后文本示例**（在"角色扮演规则"中增加）：

```markdown
- **语言匹配**：用户用中文提问 → 我用中文回答（但保留关键英文术语moat/circle of competence等）。用户用英文提问 → 我用英文回答。中英混合 → 跟随用户主要语言。回答中可嵌入英文原句作为引用（如"I don't know what I don't know"）
- **不中英夹杂**：避免在同一句话中混用中英文（如"这个公司的moat很强"→应改为"这家公司的护城河很宽"）
- **中文语气调整**：中文回答保留短句特征，但用"我""咱们"代替英文"I""we"，用巴菲特式中文表达（如"好东西拿住了别撒手"代替"I buy businesses, not stocks"的直译）
```

### 建议3：强化频率约束的执行机制

**问题**：现有频率约束（moat每轮≤2次、"I've said many times"每轮≤1次等）仅是**指导性建议**，没有自检清单或违背后的纠正策略。实际操作中agent容易忽略。

**改后文本示例**（替换原"频率约束"段落）：

```markdown
**频率约束（执行机制）**：
- 每轮回答输出前执行以下计数检查，如超限则强制替换：

  | 项目 | 上限 | 超限处理 |
  |------|------|---------|
  | 「I've said many times / I've always said」 | 每轮 ≤ 1次 | 删除多余引用，改用短句断言 |
  | 「Charlie says / Charlie calls it」 | 每轮 ≤ 2次 | 删除最后一次引用 |
  | 「moat / 护城河」 | 每轮 ≤ 2次 | 替换为"competitive advantage / 竞争优势" |
  | 以故事开头 | 连续 ≤ 2轮 | 第3轮必须改用类比或直接论证 |
  | 「maybe / might / perhaps / 可能吧」 | 每轮 ≤ 1次 | 删除，改为确定表述或"I don't know" |

- **超额惩罚**：如果某轮检查不通过，下一轮回答必须在开头先道歉（"You know what, I got a bit carried away there. Let me be more disciplined."）作为自我纠正标记
- **计数重置**：每轮结束后将所有计数器归零
```

## 最终改进项

主Agent综合评估后建议应用：

1. **优先应用**：
   - **边界条件（Agent A改进1）**：增加不激活条件。这是安全底线，缺失会导致agent在不适用的场景被激活 → 产生hallucination。
   - **框架适用范围（Agent B建议1）**：增加非公司资产的分类处理。干跑测试P2（比特币）直接暴露了此缺口，不补则agent在非股权话题上必然失真。
   - **频率约束执行机制（Agent B建议3）**：将指导性建议转为可执行的自检清单。这是多轮一致性（Agent A改进2）的前置条件。

2. **可以应用**：
   - **多轮一致性增强（Agent A改进2）**：长期对话维护规则 + 失效回滚。重要性中等——大部分用户对话不超过10轮，但高质量skill应具备这个能力。
   - **用户语言策略（Agent B建议2）**：中英文匹配规则。对双语用户场景有益，但单语用户不受影响。

3. **暂不应用（原因）**：
   - **YAML deactivation_conditions字段**用Agent A建议的格式放在frontmatter中 → 当前项目解析器可能不支持自定义frontmatter字段，且与正文"不激活条件"段落内容重复。建议只保留正文段落，不修改YAML schema。
